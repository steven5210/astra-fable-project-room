# Architecture

The package separates the agent workflow from durable execution:

- `skills/project-room/SKILL.md` supplies Astra's roles, review loop, handoff, and product acceptance workflow.
- `project_room_mcp.py` exposes local stdio tools. The plugin manifest starts it from the installed plugin root.
- `project_room.py` provides setup, diagnostics, a project/feature room registry, and the CLI equivalent of the MCP operations.
- `room.py` supplies the underlying specification-review engine: immutable specs, exact digests, persistent Claude identity, idempotency, verification, audited recovery, and bounded review rounds continued by recorded user decisions.
- `implementation.py` supplies the authorized implementation lifecycle and validation evidence, saving each model or gate stage start before the child runs so status can report accurate countdowns.
- `progress.py` derives the additive read-only `progress` object for job status from owned registry, review-turn, and handoff state plus a bounded scan of the exact owned session transcript; it never spawns, calls a model, or edits state. See [progress](progress.md).
- `heartbeat.py` writes a bounded private worker liveness record from the existing supervision loop; it never changes execution policy.
- `handoff_status.py` projects verified saved handoff metadata through an allowlist without running gates or recovery.
- `recovery.py` classifies an eligible interruption, observes host boot time and local processes, audits the stopped job read-only, and writes the immutable recovery record that an authorized successor job resumes from.
- `session_paths.py` locates only the saved UUID transcript and validates session/worktree metadata, including hashed directories for long paths.
- `qwen_guard.py` wraps an existing upstream stdio server to enforce fixed submit settings and bounded blocking waits.
- `deepseek_adapter.py` is the self-contained stdio MCP adapter for the optional DeepSeek delegate: a durable SQLite-backed job ledger, separate backend-specific key handling, request execution, and export publication. Its normalized configuration deliberately selects the fixed official DeepSeek or DeepInfra transport; the tool family, ledger lifecycle and content/reasoning separation remain shared. It imports nothing from the controller and is copied verbatim into a DeepSeek room's `profiles/` snapshot, so a later package update cannot silently change an existing room. See [the DeepSeek delegate guide](deepseek.md).
- `ao_project_room.py`, `ao_workflow.py`, `ao_delegates.py` and `ao_delegate_launcher.py` form the stock Agent Orchestrator adapter described in the AO skill reference: immutable specs, durable sends, private delegate preparation, exact-candidate verification and independent acceptance outside the repository.
- `ao_response_normalization.py` provides an audited operator-only recovery for a completed response whose valid JSON has surrounding prose. It preserves raw receipts and binds derived evidence to the exact request, spec, response and candidate; it never makes an inference call or manufactures approval.
- `ao_routing.py` generates, snapshots and offline-validates the worktree-scoped native routing configuration of a prepared AO engineer (pinned `pr-sonnet`/`pr-opus` definitions, local settings knobs and deny rules, executable identity, observed AO project rules); `ao_routing_guard.py` is the stdlib-only, deny-only `PreToolUse` guard copied content-addressed into private controller state and run by Claude's hook shell.
- `transcript_audit.py` performs a CLI-only, read-only tool-use audit of one implementation attempt's exact session transcript and its subagent files, counting `mcp__qwen-local__*`, `mcp__deepseek__*`, `Agent`, and `Task` uses without emitting any text or arguments.

Runtime data defaults to `~/.project-room` or `PROJECT_ROOM_HOME`. It is independent of plugin installation/cache paths. Claude uses dedicated saved sessions; the controller does not adopt a running Desktop conversation or scrape unrelated chat histories. A recorded message is explicit context, not implicit access to another model's full conversation.

Claude is launched with argument arrays and the configured exact model. The original `CLAUDE_CONFIG_DIR` override is preserved separately from the resolved transcript lookup directory, so an originally unset override stays unset. The review engine distinguishes a primary result producer from auxiliary usage. Identity reconciliation and local authentication recovery preserve the original evidence and never make a model call; see [recovery](recovery.md). The plugin does not extract account credentials or introduce a hosted relay.

Implementation handoff requires a clean Git source checkout and pins its baseline commit. The isolated worktree holds an uncommitted candidate. Independent gates run in that worktree; fingerprints bind working files, Git index entries, and HEAD so later changes cannot inherit stale evidence. Acceptance records the candidate. A scope discovery creates a blocker requiring a newer spec revision and renewed consensus. The Astra skill then performs integration with normal repository tools when delivery was requested; publication still follows the user's scope. These are separate from the controller's acceptance operation.

`recovery.py` only applies to an implementation job stopped by a configured model-invocation timeout or the provider's session-usage-limit signature; every other failure stays outside its classifier. Audit and recovery require host boot time strictly after the original receipt's finished time, read on Linux from `/proc/stat` `btime` and on macOS from `/usr/sbin/sysctl -n kern.boottime`; the fresh same-user process scan still runs in the same observation, and every reason (for example `restart_required` and `writer_present`) is reported together. The immutable recovery record, the failed-state snapshot, the evidence hashes, and the streamed transcript snapshot live under the private handoff directory next to the original job, and the registry table `implementation_recoveries` indexes them by room, handoff, and request ID. Lineage keeps a superseded job visible and uncertain while exempting only its authorized successor from the idle guard that otherwise blocks a room on any unresolved attempt. Every controller recovery operation acquires the room control lock, then the handoff directory lock, then the original job directory lock, then the original worker lease, in that order; the worker's pre-launch recheck already holds the handoff lock and takes only the original job lock and lease. None of these blocks, and any failure reports `cooperating_owner_active`. Private evidence, records, snapshots and transcripts are read only through user-owned directory descriptors below a trusted root (`O_NOFOLLOW` per component, `O_NONBLOCK` leaf), never through path-based opens that a swapped symlink or FIFO could redirect or block; the handoff root descriptor is bound to the directory identity captured around validation and held for the whole operation, so a root swapped afterwards is refused before any read, and every durable recovery write (preparation, dispatch, invalidation) is created, written and renamed relative to that descriptor rather than by path. The successor engine binds to the registry rows, the parent worker pid recorded at spawn, and the held lease; `launched_at` is recorded only from the spawn receipt written after the model process exists, and an interruption inside process creation stays `launch_state: unknown` and blocked.

MCP job submission and model execution are distinct. A job ID lets an active Astra turn wait in bounded intervals and lets a later turn resume after disconnect. Persistent jobs do not automatically trigger an idle Astra task. Deployment, PR publication, notifications to third parties, and schedules are outside the room's automatic lifecycle unless the user explicitly includes them.

The Qwen proxy enforces tool parameters rather than model quality or server configuration. Fable's engineering judgment determines whether a delegate is suitable. Model/window/health verification must be reported separately from tool discovery, and unavailable capabilities must stay visible.

A DeepSeek room's `profiles/` directory snapshots the adapter source and its normalized key-free configuration, including backend, exact model, endpoint and output budget, records their SHA-256 digests plus the room's granted export directory in `settings.json`'s `provider_inventory`, and grants the implementation profile `--add-dir` access to exactly that room's export directory. `implementation.resolve_provider` pins that inventory into the handoff identity at prepare time, `implementation._continue_run` re-verifies every snapshotted byte before each attempt (initial, correction, or audited successor), and the adapter refuses to serve or run a job when its own copy disagrees. Paths are pinned as strings; only the export directory's identity, not an inode, is reverified at each use, so it may be recreated when merely missing. See [the DeepSeek delegate guide](deepseek.md).

The job supervisor in `project_room.py`, and the DeepSeek adapter's own worker, both acquire a job's `worker.lock` lease before publishing the queued row and hand the held descriptor to the detached worker through `pass_fds`, rather than letting the worker race to reacquire the lease itself; a worker launched without a valid inherited descriptor falls back to a bounded retry instead of dying on transient contention, so a slow-to-start worker is never mistaken for one that vanished. See [recovery](recovery.md).

Enhancement proposals are durable room records that Astra surfaces for the user's opinion and scope approval. Astra creates or links issues through the available GitHub connector or CLI in the feature project's repository, then records the verified link; the model report itself does not execute issue operations. Filing authorization does not expand implementation scope. Missing tracker access leaves an explicit pending-filing record.
